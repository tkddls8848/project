# T4 브리프 — 데이터 품질 프로파일 리포트

## 소유 파일
- `services/crawler/profiling/quality.py` (신규)

## 목표
T3의 스키마 추론 산출물을 입력으로 데이터셋 품질 리포트를 생성한다. Gimi9가
pandas-profiling으로 하는 것과 동등한 수준이 목표다.

## 제약
- `pandas-profiling`은 현재 **`ydata-profiling`**으로 이름이 바뀌었다.
- 83,589건 규모에서 전량 프로파일링은 비현실적이다. **샘플 기반 경량 리포트를
  기본**으로 하고, 전체 리포트는 옵션으로 두어라.
- T3가 무거운 의존성 없이 표준 라이브러리로 끝냈다. 같은 판단이 가능하면
  그렇게 하고, `ydata-profiling`이 정말 필요하다고 판단되면 그 근거와 함께
  `worker_done`에 보고하라 (직접 설치하지 마라).

## 리포트 항목
결측률 · 중복률 · 타입 일관성 · 값 분포 요약 · 이상값 후보.

출력은 **JSON(기계 판독용)을 1차**로 하고 HTML은 옵션이다. 검색·조합 파이프라인이
소비할 것이므로 기계 판독성이 우선이다.

## 공통 규약

- 착수 전 `docs/superpowers/plans/2026-08-01-crawler-depth-and-link-harvest.md` 정독.
- **소유 파일 밖 수정 절대 금지.** `main.py`, `requirements.txt`, `README.md`,
  `CLAUDE.md`, `managers/file_storage.py`는 조정자 소유다. 배선이 필요하면
  직접 고치지 말고 `worker_done`에 보고하라.
- `services/crawler/tests/` 아래 신규 테스트 파일 생성은 허용. 네트워크 없이
  도는 fixture 기반이어야 한다.
- 새 런타임 의존성은 `requirements.txt`를 고치지 말고 `worker_done`에
  "필요 패키지: X>=Y"로 보고하라.
- 검증 못 한 것은 `unverified`로 표기. 추정을 사실로 쓰지 마라.
- `AskUserQuestion` 사용 금지 (조정자가 볼 수 없어 세션이 영구 정지한다).
  `orca orchestration ask`를 쓰거나, 가정을 세우고 진행 후 명시하라.

## 선행 작업 (T3) — 이미 완료됨

`services/crawler/profiling/` 패키지가 이미 있다:
- `fetcher.py` — Range 샘플링 기반 스트리밍 수신, 호스트별 동시성/딜레이/
  robots.txt 준수. 전량 수신은 명시 옵션 뒤에 있다.
- `schema_infer.py` — CSV/TSV/JSON에서 컬럼명·타입·널 비율·샘플값 산출.
  cp949/euc-kr 포함 인코딩 감지 포함. 표준 라이브러리만 사용(추가 패키지 없음).

**착수 전 이 두 파일을 읽어 실제 시그니처와 반환 구조를 확인하라. 추측 금지.**
기존 테스트 24개가 통과하는 상태다. 깨뜨리지 마라.

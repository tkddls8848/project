# T3 브리프 — fileData 파일 수신 + 컬럼 스키마 추론

## 소유 파일
- `services/crawler/profiling/__init__.py` (신규)
- `services/crawler/profiling/fetcher.py` (신규)
- `services/crawler/profiling/schema_infer.py` (신규)

## 배경
현재 fileData 크롤링은 다운로드 URL 목록에서 멈춘다. 파일을 받지 않으니 컬럼명·
타입·행수를 전혀 모른다. 이 작업이 그 다음 한 단계다.

## 결정적 제약 — 전량 다운로드는 기본값이 아니다
마스터 CSV의 파일데이터 행은 **83,589건**이다. 전량 수신은 포털 부하와 저장
용량(수 TB 추정) 문제가 있다.

- **기본 동작**: HTTP 헤더 + 선두 N바이트만 스트리밍해 스키마를 추론하는 샘플링.
  컬럼 스키마 추론에는 이것으로 충분하다.
- **전량 수신**: 별도 옵션 뒤에 두고 기본 비활성.
- 호스트별 동시성 상한, 요청 간 딜레이, 타임아웃, `robots.txt` 존중을 **반드시**
  구현하라. 정부 사이트를 두드리는 코드다. 이 부분은 타협하지 마라.

## 작업
- 입력: fileData 크롤링 결과의 `download_urls` (이름→URL 딕셔너리).
- **인코딩 감지 필수.** 한국 공공데이터 CSV는 `cp949`/`euc-kr`이 매우 흔하다.
  UTF-8 가정은 실패한다.
- 산출: 컬럼명 / 추론 타입 / 널 비율 / 샘플값.
- 스키마 추론은 `frictionless-py` 사용을 권장하되, 의존성 추가 없이 표준
  라이브러리로 하는 편이 낫다고 판단되면 그 판단과 근거를 보고하라.
- 압축(zip) 및 xlsx가 섞여 있다. 처리 못 하는 포맷은 조용히 넘기지 말고
  `unsupported`로 명시 기록하라.

## 공통 규약

- 착수 전 `docs/superpowers/plans/2026-08-01-crawler-depth-and-link-harvest.md`를 정독하라.
- **소유 파일 밖은 절대 수정 금지.** 특히 `main.py`, `requirements.txt`,
  `README.md`, `CLAUDE.md`, `managers/file_storage.py`는 조정자 소유다.
  배선이 필요하면 직접 고치지 말고 `worker_done` 본문에 보고하라.
- `services/crawler/tests/` 아래 **신규 테스트 파일 생성은 허용**한다.
  네트워크 없이 도는 fixture 기반이어야 한다. 기존 `tests/conftest.py` 패턴을 따르라.
- `find_project_root()` 복제본을 새로 만들지 마라 (CLAUDE.md의 4곳 동기화 제약).
- 새 런타임 의존성은 `requirements.txt`를 고치지 말고 `worker_done`에
  "필요 패키지: X>=Y"로 보고하라.
- 검증 못 한 것은 `unverified`로 표기하라. 추정을 사실로 쓰지 마라.
- `AskUserQuestion`을 쓰지 마라 (조정자가 볼 수 없어 세션이 영구 정지한다).
  질문은 `orca orchestration ask`를 쓰거나, 합리적 가정을 세우고 진행한 뒤
  `worker_done`에 그 가정을 명시하라.

## 이미 완료된 선행 작업 (T1)

`openapi_crawler.py`와 `file_data_crawler.py`는 이미 갱신됐다. 새로 생긴 것:

- `_detect_api_type()`가 이제 `openapi_link` / `openapi_new` /
  `openapi_parse_failed` 셋으로 분류한다.
- `CrawlData.api_type_evidence` — 분류 근거 딕셔너리.
- `CrawlData.external_endpoint_urls` — LINK형 페이지에서 추출한 외부 기관
  엔드포인트 URL 목록.
- `file_data_crawler`의 JSON-LD 파싱이 Dataset 블록 전체를 보존한다.

착수 전 이 3개 파일을 읽어 실제 시그니처를 확인하라. 추측하지 마라.
